# Backend caching and account switching

Leverframe preserves cache controls and cache identity for the selected endpoint. A correctly formed request can still miss because its prefix changed, its entry expired, or the provider did not retain it. Local protocol checks cannot establish a subscription quota multiplier.

## Backend contracts

| --- | --- | --- |
| Anthropic API Messages | Retains supported cache directives, type and TTL, plus API version and beta headers. Intentional Claude Code identity and billing-line neutralization remains in place. | Provider usage reports reads, writes and optional write lifetimes. |
| Anthropic SDK and Copilot Messages | Maps supported system, tool and message directives. A scoped transport preserves schema-valid nested tool-result controls through the SDK without changing the secure Copilot fetch boundary. | Fake upstreams prove serialization and isolation. | ChatGPT plan | Uses implicit caching and sends reusable GPT-6.2 instructions as the leading developer message on both entry points. Valid session IDs produce stable hashed cache keys. | The fallback hashes system instructions and tools, so unidentified sessions can share it. Leverframe leaves cache lifetime at the provider default. Provider cache hits and plan usage effects still require interactive observations. |
| OpenAI API | Preserves a caller cache key and sends reusable instructions as developer messages on canonical GPT-6.2 Responses requests. Claude Messages translation has an explicit-breakpoint path that requires positive model metadata. | Live discovery does not supply the explicit-breakpoint flag yet. |
| Google Gemini and Antigravity | The Google SDK reads Gemini's cache-read count. On Antigravity, measured usage preserves missing cache reads as unknown and retains the reported input total. | Gemini's public API uses implicit caching and supports explicit cache objects on eligible model/API combinations. | OpenCode Go | Sends its conversation-routing header and records uncached input, cache reads, cache writes and reported allowance separately on recognized Go Chat Completions endpoints. | The allowance is an OpenCode-reported contribution to the plan limit, expressed in dollars. | OpenCode Zen | Uses its scoped session header and reads standard cached-input counters. | Go's allowance reporting applies to Go. |

| Kimi Coding Plan and z.ai Coding Plan | Read standard cached-input counters when the endpoint returns them. | Treat these as distinct subscription endpoints. The Kimi CLI has a cache-key option and z.ai documents implicit caching. Confirm any TTL or allowance behavior for the specific plan. |
| Custom compatible endpoints | Read standard cache fields when the gateway supplies them. | Add provider controls only after confirming the endpoint's contract. |

Malformed controls on translated Anthropic routes receive a local request error before an upstream call.

OpenAI documents implicit and explicit API caching, write costs and cache lifetimes. The ChatGPT plan preview documents a narrower request surface. Leverframe keeps implicit caching and the provider default lifetime on that route. [OpenAI caching guide](https://developers.openai.com/api/docs/guides/prompt-caching) · [ChatGPT plan preview](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations)

Gateway input excludes reads and writes, and its output already includes reasoning. Leverframe avoids adding either twice.

## Reading usage

Measured logs preserve provider fields independently, so known cache-write lifetimes can appear even when the aggregate remains unknown. When ChatGPT Plan reports an input total and omits cache reads, the log records the total and leaves fresh input unknown. Client protocol formatting keeps its compatibility defaults separate. An omitted count establishes neither a cache hit nor a miss.

A November 19, 2026 sample from the last 20,000 MacBook log lines retained one final usage event per request for that UTC date. ChatGPT plan reported positive cache reads in 12 of 44 requests, and OpenCode Go in 79 of 80. These counts show that upstream reuse occurs on both routes. The workloads, models, and session histories differ, so the counts cannot rank provider efficiency or estimate subscription savings.

A later sample on November 19 covered 20 completed GPT-6.2 Astra requests in one Claude session on the ChatGPT plan route. The translated usage log showed cache reads on 14 requests and zero reads on six. Cached input accounted for 1,453,312 of 2,391,406 input tokens (60.8%). The profile had Preserve prefix enabled for the route when checked. Zero reads occurred between large hits seconds apart. These logs capture usage and timing. They lack evidence that the outgoing OpenAI request prefix stayed identical across the affected requests.

The older sample came from Claude-compatible usage logs. The SDK could turn an omitted upstream cache-read count into zero, so the six zeros cannot independently prove six upstream misses. Comparing stored message digests showed that adjacent requests shared all but one to three messages of the previous request. The session showed no ToolSearch activity in the sample. These checks narrow the search to final request translation, upstream cache behavior, and response accounting.

Claude Code computes its status line hit ratio from cached tokens as a share of all session input tokens. Its miss count can include partial reads and applies to the main conversation. The status line shows Claude Code's cache lifetime and most recent miss diagnosis. On the ChatGPT plan route, verify actual reuse with OpenAI's cache-read token counts. Leverframe leaves retention at the provider default. [Claude Code status line fields](https://code.claude.com/docs/en/statusline#prompt-cache-fields)

Effort comes from the route's capability metadata when the provider reports it. Anthropic model discovery preserves the individual effort flags. Its translated requests can now send `xhigh` for models that support it. OpenAI's public model list lacks these flags, so the canonical API-key route uses the documented GPT-6.2 Astra and Sol levels only when its catalog has no explicit list. The ChatGPT plan route uses its own account catalog. Changing top-level effort can affect cache reuse, so hold it fixed during cache comparisons. [Anthropic model list](https://platform.claude.com/docs/en/api/models/list) · [Anthropic effort](https://platform.claude.com/docs/en/build-with-claude/effort) · [OpenAI model capabilities](https://developers.openai.com/api/docs/models)

A follow-up read of the last 24 MB of local inference logs kept one final usage event per request on November 19 UTC. OpenCode Go showed positive reads on 176 of 179 requests and 98.1% of input tokens from cache. ChatGPT Plan showed positive reads on 58 of 159 and 33.7% of input tokens from cache. The 77 shorter Anthropic passthrough requests showed zero reads across 81,798 input tokens. The sample contained no completed Antigravity usage events. Workloads and model mix vary by route, so use these numbers as baselines within each route.

Expanding that read to the last 36 MB found live Anthropic cache reads on 17 of 96 passthrough requests. The largest recorded input was 163,968 tokens. This confirms reuse on the passthrough route. It says nothing about Antigravity or the amount of subscription allowance consumed.

The OpenCode Go Chat Completions token parser recognizes the configured `/zen/go/v1` endpoint and the official `/inference/go` aliases. It retains `opencode.allowance` as `openCodeGoAllowanceUsd` in measured usage when OpenCode supplies the value, including zero. The translated HTTP proxy records it under `upstream_usage`. [OpenCode Go endpoints](https://dev.opencode.ai/v2/docs/console/go) · [OpenCode usage fields](https://dev.opencode.ai/docs/console/api/inference)

Antigravity preserves `thinkingConfig` in its subscription request envelope and unwraps upstream usage for the Google SDK. Its catalog does not report selectable effort levels for the ten models in the local snapshot. The bridge rejects fields outside its subscription contract, including public Gemini's `cachedContent` field. The translated HTTP proxy's `upstream_usage` event distinguishes omitted cache data from explicit zero and reports the upstream prompt total when available. Antigravity cache reuse and support for explicit cache objects still need subscription-specific evidence. [Gemini context caching](https://ai.google.dev/gemini-api/docs/caching/) · [Google usage metadata](https://ai.google.dev/api/generate-content)

The GPT-6.2 ChatGPT plan transport now sends local tools in stable name order. This removes misses from pure tool reordering. A real tool addition or schema change still changes the prefix. Leverframe now also replays the original item ID with OpenAI's encrypted reasoning and accepts older signatures that carry only the encrypted content. The SDK-facing usage keeps omitted reads distinct from explicit zeros. [OpenAI prefix guide](https://developers.openai.com/api/docs/guides/keep-prefix-unchanged) · [OpenAI reasoning guide](https://developers.openai.com/api/docs/guides/reasoning)

New ChatGPT Plan backends record local cache diagnostics by default for all Plan models. Set `LEVERFRAME_OPENAI_CACHE_DIAGNOSTICS=0` to turn them off. On GPT-6.2, launching with `LEVERFRAME_OPENAI_CACHE_DIAGNOSTICS=1 claudeplus` also asks OpenAI to compare a normal request against the recent completed response for the same session, model, and credential. The comparison adds no inference request. OpenAI can return an inconclusive result. [OpenAI prompt cache diagnostics](https://developers.openai.com/api/docs/guides/prompt-caching/diagnostics)

Recent agent research found silent request-side and usage-reporting cache defects. Research on coding agents also found that trimming old tool outputs can raise overall cost when the rewrite loses a reusable prefix. Compare measured input, cached input, and completed work before making automatic history rewrites more aggressive. [Zhang et al.](https://arxiv.org/abs/2610.34817) · [Yang et al.](https://arxiv.org/abs/2611.22238)

The offline regression suite uses real SDK conversion against fake HTTP and SSE responses. It covers endpoint boundaries, valid controls, malformed controls, streaming, cancellation, concurrent calls, and request isolation. Those fixtures do not measure actual provider savings.

## OpenAI optimization priorities

The [OpenAI cache recovery plan](superpowers/plans/2026-11-19-openai-cache-recovery.md) uses these diagnostics to separate client-side prefix repairs from unexplained upstream misses.

The first 25 completed requests in the November 19 live Astra diagnostic run recorded 571,520 cached tokens out of 2,714,327 input tokens (21.1%). Six responses reported cache reads and 19 reported zero reads. All 25 reported zero cache-write tokens. All 22 diagnostic outcomes were `unavailable`, including responses that reused cache. The cache-read counter establishes reuse. A zero write count on this route gives no evidence about the subscription quota formula or how long OpenAI retained a prefix. [OpenAI diagnostic outcomes](https://developers.openai.com/api/docs/guides/prompt-caching/diagnostics)

The `[leverframe openai cache]` line puts provider token counts and outcomes next to Leverframe's local finding for the same completed request. It reports the model, process-local session tag, model instance tag, request sequence, timestamps, and comparison baseline state. A recent baseline also reports the first changed section, shared input item count, age, and whether another request started since that baseline. An intervening request can still be in flight or can have failed. Use timestamps to check overlap. A zero read with an unchanged outgoing prefix yields `stable-prefix-zero-read`, even if OpenAI returns `unavailable`. Missing read counts leave the finding unknown.

The log keeps prompt text, tool schemas, raw session keys, response IDs, and credentials out of diagnostics. Upstream comparison mode can record OpenAI's request ID for support correlation and retains the separate `[leverframe openai prefix]` line. The 15-minute local comparison window governs the diagnostic baseline. Provider cache retention follows the upstream route.

### Compare session logs offline

Use `leverframe-cache-report` from the installed package, or run the script directly from this checkout. Give it one or more `leverframe.log` files from the relevant Claudeplus launches.

```sh
node scripts/cache-session-report.mjs --input /path/to/first/leverframe.log --input /path/to/second/leverframe.log
```

The report deduplicates requests by model instance and sequence. It groups by model, session, effort, and tool mode so Astra and Luna stay separate. It distinguishes stable-prefix zero reads, changed-prefix zero reads, absent counters, and terminal failures. Use `--since` and `--until` with UTC timestamps to restrict the report to a task window. The overlap count uses observed time intervals in the supplied logs. Canceled requests without a terminal observation can leave gaps.

Use `--support` to include request IDs, when present, for repeated stable-prefix zero reads with a baseline age of at most 30 seconds and no observed overlap. Keep collection on ordinary interactive work. The report reads files and prints JSON locally. It makes no provider requests. Older lines without request sequence and timing appear in `unclassifiedLines`. Token totals include usage from failed attempts when the provider supplies it. A missing split leaves fresh input unknown for that request. The report gives the number of observations behind each token total.

Launch with `LEVERFRAME_OPENAI_APPEND_ONLY_TOOLS=1 LEVERFRAME_OPENAI_CACHE_DIAGNOSTICS=1 claudeplus` to test new tool declarations on your usual interactive requests. When the input extends the previous request and existing tool definitions match, new local tools go in an `additional_tools` item at the end of the current input. Later requests replay the item at its original position. A rewritten prefix, tool removal, schema change, or a tool already called before its proposed declaration starts a new baseline with the current tool list. [OpenAI tool declarations](https://developers.openai.com/api/docs/guides/tools-tool-search) · [ChatGPT plan preview](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations)

## Local caching experiments

Open `leverframe providers`, choose **Cache settings**, then select an enabled provider. **Preserve prefix (experimental)** skips Leverframe's duplicate tool-result reduction and paid summary pass for that provider. It leaves provider-side caching controls in place. **Current behavior** restores the usual local context policy. The setting applies to subsequent requests.

Leverframe already supports [exact duplicate tool-result reduction and local evidence references](context-evidence.md). It can also reuse eligible summaries from its opt-in paid summary stage. Those policies change how much context travels upstream. An experiment should compare them with a prefix-preserving baseline on the same provider, model, account and task, using separate cache keys to avoid sharing a warmed prefix across arms.

A November 2026 preprint ran more than 20,000 coding-agent trials with open models. Dropping old observations lowered modeled costs without cache discounts, but raised them by 38% to 116% when cached input cost one tenth of uncached input. Even an append-only exact-reference pilot increased modeled cost by about 4% over 115 tasks, where fixed-action replay predicted a saving. Measure work to successful completion, including extra turns and evidence retrieval. [Context Has a Price](https://arxiv.org/abs/2611.22238) · [Appendix H](https://arxiv.org/html/2611.22238v1)

Track provider-reported uncached input, cache reads, cache writes, output, latency to the first token, completion quality and allowance when available. Log only privacy-scoped fingerprints to diagnose where a prefix changed. A stable fingerprint indicates reusable input structure. The provider's reported usage establishes a cache hit.

TokenPilot provides an approach for stabilizing prompts on ingestion and batching context eviction after it loses value. Trial this on captured fixtures and opt-in tasks before changing defaults. Exact caching of pure local computations can use implementation version, arguments and content hashes to determine freshness. CacheBlend and similar KV reuse techniques need access to the model server's intermediate state, which the hosted APIs do not expose. [TokenPilot](https://arxiv.org/abs/2606.17016) · [ToolCaching](https://arxiv.org/abs/2601.15335) · [CacheBlend](https://arxiv.org/abs/2405.16444)

### Retrieval as a cache experiment

The [local retrieval guide](local-retrieval.md) shows how to opt in to exact file and identifier lookup and measure its cost on your provider route. The tools return locations first and check file content before returning source on demand. Leverframe also has encrypted session evidence for exact reference lookup. Its vector-memory module validates embedding records for future retrieval experiments. [Leverframe context evidence](context-evidence.md) · [RepoCoder](https://aclanthology.org/2023.emnlp-main.151/)

Keep one stable workspace packet at the start of a session or immediately after compaction. Freeze its exact order and content for that conversation. Append new evidence as a tool result after the existing prefix. To reuse a tool result, check the workspace, tool version, arguments and revisions of the files it depends on. Check dirty file contents as well as the Git revision. Limit reusable results to reads with verifiable freshness and access scope. Treat retrieved text as data and fall back to the original tool when provenance, freshness or relevance is uncertain. [OpenAI prefix guide](https://developers.openai.com/api/docs/guides/keep-prefix-unchanged) · [ToolCaching](https://arxiv.org/abs/2601.15335)

The main risk is changing an inexpensive cached prefix or adding irrelevant content that triggers extra turns. In a study of coding agents, adding retrieved code reduced read and search commands by 18% to 34% but raised modeled cost by 33% to 42% at a 10% cache-read price. A separate exact-reference pilot preserved previous messages and still increased modeled cost by 4% because the observed runs performed more work. Semantic similarity alone also gives weak evidence that a stored answer is correct for the current repository state. Cache source evidence first and leave final-answer reuse outside the initial experiment. [Context Has a Price](https://arxiv.org/html/2611.22238v1) · [Semantic cache correctness](https://arxiv.org/abs/2611.02498)

Compare retrieval with Preserve prefix on matched tasks and separate warmed sessions. Measure task success, re-reads, first-text latency, total steps, fresh input, cache reads and writes, and reported plan allowance where available. For example, at a 5% cached-input rate, 20,000 reused input tokens cost the same as 1,000 fresh ones. Replacing that reusable context with 2,000 new tokens lowers the prompt length while doubling that part of input cost. Prefer improvements in cost per successful task to increases in the displayed hit percentage alone. [OpenAI cache rates](https://developers.openai.com/api/docs/guides/prompt-caching) · [Context Has a Price](https://arxiv.org/html/2611.22238v1)

## Account controls

Account balancing and quota failover default on, with separate switches in the existing settings menu. Add API accounts or sign in to another ChatGPT account through account management. Credential import requires an explicit confirmation. Claude Code subscription credentials do not join this pool.

The remaining-quota threshold defaults to 10 percent. Set it to 0 to disable proactive threshold switching, or choose a finite percentage below 100. Proactive switching requires both balancing and failover on, recent verified quota data, and a comparable better account. Unknown data does not become an invented balance. All-low accounts remain usable until actual limits block them.

The local freshness limit is 60 seconds for proactive comparisons. It does not claim that provider quota resets after a minute, and it does not clear blocked or authentication-failure states. Weekly-only Codex windows work without a five-hour assumption. The settings activity display retains the actual latest switch reason and timestamp across ordinary follow-up requests.

Rebuilt files affect newly started Leverframe sessions. Existing per-session proxy processes keep the code they loaded. Start a new interactive Claude Code session after installation to observe the current adapter and compare provider-reported cache usage on the same model and effort.
